# Spec: 整合包任务书汉化翻译平台

**状态：** approved
**日期：** 2026-10-18
**取代：** `.scratch/index-mvp/spec.md`（索引 MVP，其「明确不做翻译」的排序被用户 2026-10-18 推翻）

## Problem Statement

玩家想玩一个英文整合包，任务书全是英文，看不懂任务目标。社区里 VM 汉化组、CFPA 团队
各自做了一部分，但**没有一个入口能提交「我想要这个包的中文」**，也没有一条**自动化的产出链路**
把提交变成可下载的汉化。

上一轮把站点做成了「只放链接的索引站」（ADR-0006），一个字都不翻。用户 2026-10-18 明确推翻：

> 我这个网站本来就是让玩家提交整合包链接，然后我们就可以启动一套自动化翻译流程对它进行翻译。
> 如果这个整合包没有 FTB Quests 任务模组的话，就直接跳过不翻译。
> 然后我们还会提供下载链接，比如对应的 GitHub 仓库链接，还会上传到夸克网盘，提供夸克网盘链接作为国内镜像。

即：**「求」不是索引的附属验证手段，而是站点的输入端；翻译流水线不是「以后再说」，而是站点的核心。**

同一套模式用户已在**光影汉化站**（`E:/project/shader-i18n-site`，线上 `shader.mccnp.top`）跑通，
本 spec 的架构**照搬那套骨架**，不另造一套。

## Solution

站点从「静态单页索引」变成「有后端的翻译平台」，链路为：

```
玩家提交整合包链接
      ↓
Cloudflare Worker 校验链接 → 写 KV 队列（权威状态源）
      ↓
维护者口令门禁 → 一键触发 GitHub Actions
      ↓
pipeline：筛候选（只做 FTB Quests）→ 站点术语记忆精确命中 → LLM 分块翻译
      ↓
质量闸门 validate-quests（键集合 + 色码 + 占位符 + SNBT 结构）
      ↓
覆盖式补丁包 zip（玩家解压覆盖到整合包根目录）
      ↓
双通道分发：GitHub 仓库 + 夸克网盘镜像
      ↓
详情页给 zip 下载入口 + GitHub 仓库链接 + 夸克镜像按钮
```

**只做 FTB Quests 任务书。** 整合包不含 FTB Quests 时直接跳过，不翻译、不产出。
非 FTB 任务书系统（如 SkyFactory 5 用的 Checklist）不在范围内。

**产出形态是覆盖式补丁包 zip**，与社区主流一致（CFPA `Modpack-GuideBook-i18n`、VM 汉化组、
Kiwi233 `Translation-of-GTNH` 都在这么做）。补丁包必须自带备份提示，并明写「上游更新后可能失效」。

## 已决（2026-10-18 用户确认，全部沿用光影站做法）

1. **关站判据**：基于**提交量与产出量**，不是访问量。连续 6 个月无新增提交且无新增产出才考虑关站。
2. **术语记忆来源**：自建 `glossary.json`，从 CFPA 模组术语库起步做种子，之后随翻译回写增长。
3. **LLM 网关**：免费层优先（公开 API），失败落自建网关模型池。
4. **内嵌包产出方式**：整体覆盖式；落地前先验证 SNBT 无损往返。无损则按 quest ID 合并作可选增强。
5. **审核环节**：无人审核，唯一质量闸门是校验器。

## User Stories

### 提交与队列

1. 作为玩家，我可以粘贴一个整合包链接（CurseForge 或 Modrinth），提交翻译请求。
2. 作为玩家，提交时非法链接（不是整合包、域名不认、项目不存在）当场被拒并给出原因。
3. 作为玩家，我可以留一个邮箱，产出完成时收到通知（可选）。
4. 作为玩家，我可以留一句话说明（可选）。
5. 作为玩家，同一整合包重复提交只更新时间，不重复入队。
6. 作为玩家，我提交后能在队列里看到我的请求及其状态。
7. 作为玩家，队列状态自动刷新，我不需要手动刷新页面。
8. 作为玩家，我能看到每个请求的状态：待翻译 / 翻译中 / 已完成 / 镜像缺失 / 失败。
9. 作为玩家，失败的请求能看到失败原因。
10. 作为玩家，提交频率有每 IP 每天上限，超限时收到明确提示。
11. 作为维护者，队列的权威状态源是 KV，任何镜像（如腾讯文档）失败都不阻断主流程。

### 翻译流水线

12. 作为维护者，我能用一条命令在本地离线跑通翻译流水线（`npm run translate -- --ids a,b`）。
13. 作为维护者，流水线只处理含 FTB Quests 的整合包；不含的直接跳过并记原因。
14. 作为维护者，流水线按整合包版本筛选候选，排除自带中文、已是最新汉化、无英文源的条目。
15. 作为维护者，流水线先查站点术语记忆，精确命中时一次 LLM 都不调。
16. 作为维护者，未命中术语记忆的文本按块送 LLM，块大小可配（默认 60 行）。
17. 作为维护者，LLM 分块回退率超阈值时整块重试，整体超阈值时判失败、不写文件。
18. 作为维护者，流水线为每条产出写头部标注「AI 初翻，未人工校对」。
19. 作为维护者，翻译产出的英文↔中文对照回写进 `glossary.json`。
20. 作为维护者，每条整合包独立超时，超时只让该条失败，其余继续。
21. 作为维护者，我能看到流水线的失败原因写回队列状态。

### 质量闸门

22. 作为维护者，校验器检查译文键集合与英文源一致（缺键/多键判失败）。
23. 作为维护者，校验器检查色码 `&`/`§` 序列合法（畸形序列判失败）。
24. 作为维护者，校验器检查占位符种类与数量一致（`%s`、`%1$s`、`%%` 等）。
25. 作为维护者，校验器检查 SNBT 结构可解析、可序列化（内嵌布局）。
26. 作为维护者，校验器检查产出文件无 BOM、编码为 UTF-8。
27. 作为维护者，校验失败即中止该条产出，不写文件、不登记、不留半个文件。
28. 作为维护者，找不到英文源时判失败，绝不退回「自检」产生假绿灯。

### 覆盖式补丁包

29. 作为玩家，我能下载一个 zip，解压覆盖到整合包根目录即可生效。
30. 作为玩家，zip 内路径与整合包内路径一一对应，不需要我手动找位置。
31. 作为玩家，zip 内自带 README，写明「替换前请备份游戏」与「上游更新后可能失效」。
32. 作为玩家，zip 内自带许可与署名文件（CC BY-NC-SA 4.0，署名 CFPA 团队与相关模组作者）。
33. 作为维护者，分离布局包只需新增文件，不触碰玩家任务数据。
34. 作为维护者，内嵌布局包就地改写 `chapters/*.snbt`，且改写前后 SNBT 无损往返（验证过才允许）。
35. 作为维护者，打包是幂等的：同一输入连续跑两次产出逐字节相同的 zip（时间戳除外）。

### 镜像、发布与下载

36. 作为玩家，我在详情页能看到 GitHub 仓库下载链接。
37. 作为玩家，我在详情页能看到夸克网盘镜像按钮（仅当镜像成功时渲染）。
38. 作为玩家，镜像失败时页面不显示夸克按钮，不显示假链接。
39. 作为维护者，镜像失败不阻断发布，只让该字段留空。
40. 作为维护者，发布流水线顺序是「测试 → 校验 → 构建 → Worker → Pages」。
41. 作为维护者，发布用显式路径 `git add`，禁止 `git add -A`。
42. 作为维护者，Worker 必须先于 Pages 部署，否则线上 API 是旧版本。

### 维护者门禁与触发

43. 作为维护者，我在管理区输入口令后能触发翻译。
44. 作为维护者，口令错误时触发被拒（401）。
45. 作为维护者，触发成功后条目立即置为「翻译中」，避免重复点击重复触发。
46. 作为维护者，我可以选择只重试失败条目（默认不重试，避免烧额度）。
47. 作为维护者，我可以从网关实时模型列表里多选模型（口令门禁后）。
48. 作为维护者，模型选择必须命中网关实时列表，任意字符串不透传进 workflow。

### 状态模型与文案

49. 作为玩家，六态状态模型与文案准确反映平台定位（内嵌从「不可做」改为「可做（覆盖式）」）。
50. 作为玩家，非 FTB 任务书系统（如 Checklist）的包显示为「无任务书（非 FTB Quests）」，不误导。
51. 作为玩家，详情页显式出现「不同来源汉化不能同时安装」警告，不可折叠隐藏。
52. 作为维护者，关站判据写入 ADR，基于提交量与产出量。
53. 作为维护者，ADR-0004 重写为「分发衍生作品」的许可与署名约束。
54. 作为维护者，GLOSSARY 更新：内嵌布局从「不可做」改为「可做（覆盖式）」。
55. 作为玩家，站点在桌面（≥1200px）与移动（≤480px）两个断点下都可用。
56. 作为玩家，站点键盘可达、屏幕阅读器可读（无障碍）。
57. 作为玩家，站点零构建、零 CDN，双击可开（静态部分）。
58. 作为玩家，所有外部结论可追溯到来源链接与抓取时间。

## Implementation Decisions

### 架构照搬光影站，逐环节对应

| 环节 | 光影站实现 | 本项目 |
|---|---|---|
| 采集 | Actions 每日同步目录 | 已有：`scan-cf500.tsv` + `pack-metadata.json` |
| 提交 | `/request` → Worker（口令 + CORS + 链接校验）→ KV 队列 | 同一套 |
| 触发 | Worker 调 GitHub API `workflow_dispatch` | 同一套 |
| 翻译 | `pipeline.mjs`：筛候选 → 术语记忆精确命中 → LLM 分块 | 目标换成 FTB Quests 的 SNBT |
| 闸门 | `validate-lang.mjs`：键集合 + `§` 格式码 + 占位符 + BOM | 色码 `&` + 占位符 + 键集合 + SNBT 结构 |
| 镜像 | `mirror.mjs` 上传夸克，失败不阻断、留空不渲染按钮 | 同一套，产物是补丁包 zip |
| 发布 | 显式路径 `git add` → push → `deploy.yml` | 同一套 |
| 下载 | 详情页给文件下载 + 夸克镜像按钮 | 详情页给 zip 下载 + GitHub 仓库 + 夸克镜像 |

### 技术栈（已定）

- **站点**：自包含静态 HTML（内联 CSS，零构建，零 CDN），数据构建器用 Node 无依赖脚本。
- **后端**：Cloudflare Worker + KV（`TRANSLATION_QUEUE` binding）。
- **CI**：GitHub Actions（`translate.yml`、`deploy.yml`）。
- **测试**：`node:test`，唯一 devDependency 是 `wrangler`。
- **两个断点**：桌面 ≥1200px、移动 ≤480px，同一文件内媒体查询。

### 状态机

`待翻译 (pending)` → `翻译中 (translating)` → `已完成 (done)` / `镜像缺失 (done-unmirrored)` / `失败 (failed)`

状态权威源是 KV。同一整合包重复提交只更新 `updatedAt`。

### 术语

- **模组术语库**（只读，来源是别人）：从模组 jar 与 CFPA 成品抽取的权威译名表。
- **站点术语记忆**（可写，来源是我们自己）：本站产出累积的英文↔中文对照，落在 `glossary.json`。
- 两者**必须分开**，混用会造成破坏性错误（光影项目已踩过）。

## Testing Decisions

- 所有纯函数（链接解析、候选筛选、术语记忆命中、SNBT 解析/序列化、校验器、打包）必须有单元测试。
- 校验器必须覆盖：缺键、多键、畸形色码、占位符差异、BOM、找不到英文源——每条都要有「应判失败」的测试。
- SNBT 无损往返必须有「解析 → 序列化 → 再解析」逐字节相同的测试，且用真实整合包样本做夹具。
- Worker 的纯函数（`selectTranslateTargets`、链接解析、限流判定）必须有单元测试。
- 打包幂等性测试：同一输入两次产出逐字节相同（时间戳除外）。
- 流水线端到端测试：用夹具整合包跑通「筛候选 → 翻译（桩）→ 校验 → 打包」，断言产出 zip 内容。
- 现有 64 项测试必须保持全绿。

## Out of Scope

- 非 FTB Quests 任务书系统（Checklist、Better Questing 等）。
- 账号系统、广告。
- 人工审核环节（唯一闸门是校验器）。
- 整合包本体分发（只分发任务书汉化）。
- 消歧、术语库编辑器 UI。

## Further Notes

- **平台 Windows**。子代理用 PowerShell 读中文文件会乱码，用 `node -e` 或直接读文件。
- **Node 在 Windows 下不能直接 import 绝对路径**（`ERR_UNSUPPORTED_ESM_URL_SCHEME`）。临时脚本放进仓库目录用相对路径 import，或转成 `file://` URL。
- **CF API key 只从 `CF_KEY` 环境变量读**，不落盘、不入库。需要时找用户要。
- **CF API 批量接口**：`POST https://api.curseforge.com/v1/mods`，body `{modIds:[…]}`，一次最多 1000 个 id。
- **`research/tmp/` 已被 `.gitignore`**，可安全往里丢调研残渣。
- **`dist/` 与 `site/index.html` 已 gitignore**，`site/data.json` 是例外。
- **验收条件里绝不能留开放判断项**——开放判断项就是给 implementer 挖坑。有疑问先把答案查清楚写进工单。
