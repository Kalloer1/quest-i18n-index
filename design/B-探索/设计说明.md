# 方向 B「探索」· 设计说明

交付物：`design/B-探索/index.html`（自包含，内联 CSS + 极少量内联 JS，双击即可打开，不依赖构建与 CDN）。
界面语言简体中文；数据来自真实 `design/demo-data.json`（22 个整合包，图标与截图都用真实 URL）。

---

## 一、方向先定调（UI 设计师）

**玩家来这里是为了「发现我还能玩什么」。** 所以第一屏不是状态表，而是世界的入口。

1. **暗底 + 封面当唯一亮源**。基底压到近黑冷蓝 `hsl(224 34% 5%)`，顶部只留一层极淡的极光做纵深。
   颜色预算几乎全给封面图，界面自己退到后面去。这是 CurseForge / 游戏启动器那类「封面驱动」的气质。
2. **一屏一个主行动**。首屏只有「从封面开始逛」这一个高饱和按钮，其余是描边按钮与文字链接。
3. **留白即节奏**。区块间距走 96–128px 刻度，桌面网格固定三列、卡间距 20–36px；
   一屏看到 6 张卡而不是 12 张。滚动本身是体验的一部分，这点是刻意的。
4. **状态说人话**。「已可下载」不该是一枚冷徽章，而是一件值得高兴的事：
   列表卡片底部是叙事句（「中文已就绪，下载即用」），详情页的标题直接是结论
   （「好消息：这个包的任务书已经有中文了」）。
5. **不为了好看牺牲可用性**。叙事归叙事，冷标签（已可下载 / 自带中文 / 待翻译）仍然显式保留，
   因为玩家需要一眼判断，而不是读散文。

### 语义化令牌（不散写样式）

- 颜色：`--bg / --bg-2 / --surface / --surface-2 / --ink / --ink-2 / --ink-3 / --line`，
  以及三态色 `--ready`（青绿 163）`--builtin`（靛蓝 232）`--pending`（琥珀 38）。
- 间距：4/8 基准刻度 `--s1…--s10`（4→128px），纵向节奏统一。
- 圆角 `--r-sm/md/lg/pill`、阴影 `--sh-1/2`、动效 `--dur-1/2/3` + `--ease`/`--ease-out`。
- 配色关系：单色冷蓝邻近为主，三个状态色作为「小面积强调」，彼此色相拉开。

### 字号阶梯

`h1 clamp(34px,6.6vw,76px)` → 区块标题 26–22px → 卡片标题 19px → 正文 16px → 次要 13–14px。
标题收紧字距（`-.03em`），中文段落用 `text-wrap:pretty` 减少「最后一行只剩一两个字」的孤字。

## 二、四个视图（信息架构）

单文件内用 hash 路由实现，切换时只播一次 220ms 的淡入上移，并把焦点交给新视图的标题
（键盘与读屏用户不用从顶栏重新 Tab 一遍）。

| 视图 | 路由 | 要点 |
|---|---|---|
| 列表页 | `#/` | Hero + 三态图例 + 筛选条 + 封面网格 + 空状态 |
| 详情页 | `#/pack/<slug>` | 模糊头图、大状态叙事、截图浏览、文件情况、安装三步、署名 |
| 安装说明 | `#/install` | 三步操作、正确/错误对照、路径一键复制 |
| 关于与许可 | `#/about` | 署名（CFPA 团队 + 相关模组作者）、CC BY-NC-SA 4.0、非商业声明 |

**为什么详情用独立路由而不是弹窗**：截图浏览需要横向空间，且玩家常要把某个包发给队友；
独立路由可复制链接、可前进后退，也不会出现「弹窗里再开弹窗」的焦点陷阱。

## 三、三种状态的表达（本设计的核心主张）

### 派生规则（与站点接口一致，非编造）

```
siteStatus === '自带中文'                  → 自带中文
siteStatus === '待翻译' && zhFiles > 0     → 已可下载（本站已产出）
其余                                       → 待翻译
```

**注意：这批真实数据里「已可下载」是 0 项。** 15 条「待翻译」的 `zhFiles` 全为 0。
我没有为了画面好看去编几个「已可下载」的包，而是：

- 三态图例（首屏第二块）把三种状态的含义、颜色、图标、文案全部讲清楚，即使当前列表里没有第 3 种；
- 筛选条的「已可下载 0」保持可见且可点，点了会进入**空状态**并指向下一步（「去看待翻译的 15 个包」）；
- 统计区如实显示 `0 个已可下载`。

### 三重编码（色盲安全）

色相只是第二线索，**形状 + 文字**才是主线索：

| 状态 | 色相 | 图标形状 | 列表叙事句 | 详情页结论文案 |
|---|---|---|---|---|
| 已可下载 | 青绿 163 | 向下箭头入盘（下载） | 中文已就绪，下载即用 | 好消息：这个包的任务书已经有中文了 |
| 自带中文 | 靛蓝 232 | 立方体包裹（包内自带） | 包里自带中文，别白找 | 这个整合包本来就带中文，不用来我们这儿找 |
| 待翻译 | 琥珀 38 | 时钟（排队中） | 还差翻译，可以催更 | 这个包的中文还没做，但你可以催 |

图标为内联 SVG（线宽 2.4–2.6、统一 24 视框），不依赖 emoji 字体，渲染一致、可缩放。
三个色相对深底对比度均在 9:1 以上，灰度打印时也能靠明度差与形状区分。

### 叙事如何「不说谎」

状态句里嵌真实数字：自带中文的包写「共 69 个中文文件」，待翻译的包写「有 61 个英文源文件」，
这些数字直接来自数据字段，而不是「很快」「大量」这类填充词。

## 四、动效规格（微交互动效专家）

原则：有目的、便宜（只动 `transform` / `opacity`）、可降级。所有时长都用同两条缓动令牌。

| 触发 | 属性 | 时长 / 缓动 | 它沟通了什么 | 降级 |
|---|---|---|---|---|
| 卡片入场（首屏与每次筛选后） | `opacity` + `translateY(22px→0)` + `scale(.985→1)` | 620ms，`--ease-out`，逐张 +42ms 递增 | 新内容到位，且顺序即列表顺序 | `prefers-reduced-motion` 下动画被压到近零 |
| 卡片悬停/聚焦 | `translateY(-6px)`、边框变亮、阴影加深 | 220ms，`--ease-out` | 「这张可以点」 | reduced-motion 下不做位移 |
| 封面悬停 | `scale(1.01→1.055)` | 640ms，`--ease-out` | 图片是主角，轻微景深变化 | 同上，固定 1.01 |
| 视图切换 | `opacity` + `translateY(10px→0)` | 220ms，`--ease-out` | 换页了 | 时长压到近零 |
| 筛选点击 → 骨架 → 内容 | 骨架 3–6 块，再替换为卡片 | 200ms（reduced-motion 60ms） | 正在取数，别以为卡住了 | 直接出内容 |
| 骨架扫光 | 伪元素 `translateX(-100%→100%)` | 1.15s linear 循环 | 尚在等待 | 循环关闭 |
| 截图切换 | 主图 `opacity`+`scale(1.02→1)` | 420ms，`--ease-out` | 换图了 | 时长压到近零 |
| 按钮按下 | `scale(.98)` | 140ms | 已收到点击 | 保留（极短且无位移风险） |
| 反馈条（复制/下载/催更） | `translateY(140%→0)` + `opacity` | 220ms，`--ease-out` | 操作有结果 | 时长压到近零 |

**性能说明**：全部动画只碰 `transform` / `opacity`，没有动画 `width` / `top` / `margin`，
骨架扫光也没用 `background-position`（那是重绘，不是合成）。卡片入场用 `animation-delay` 递增而非 JS 计时器逐个触发。

**首屏过渡 / 加载骨架**：列表初始由脚本渲染，先铺骨架再出内容。
真实站点只需把 `renderList()` 里的定时器换成 `fetch`，骨架与 `aria-busy` 的语义都不用改
——这也是我把它写成「模拟异步」的原因，而不是装饰性动画。

## 五、截图浏览与「没有截图」的降级

真实数据里 22 个包有 9 个没有截图（`screenshots: []`），所以降级是常规态，不是边缘情况。

- **有截图**：主图 16:9 + 底部缩略图条（`scroll-snap`，`aria-current="true"` 标出当前张）。
  键盘：`←/→` 在缩略图间移动并同步切换主图，`Home/End` 跳首尾；主图 `alt` 会更新为
  「游戏内截图，第 3 张，共 4 张」。切换时缩略图自动滚入视野。
- **没有截图**：不放灰色空框。改成一张「图标 + 极光渐变」的占位封面，并写清
  「它的页面里只有图标，所以我们不放空占位图来凑版面」，再给出可执行的下一步（去平台搜包名）。
- **列表卡片同理**：没有截图时用大图标 + 渐变做降级封面，右上角标「暂无截图」；
  并且此时**不再**叠加左下角的小图标（避免同一个图标出现两次）。
- **头图去重**：详情页头图用的是第一张截图，但做了模糊压暗处理（`blur(26px)` + 1.1 倍内缩），
  只当氛围，避免与下面「游戏内截图」第一张完全重复。
- **图片加载失败**：任何 `img` 失败都会退回图标占位；只有 64px 小图标失败时只隐藏它，
  不会把整张封面换成占位图。

## 六、无障碍（无障碍专家 · WCAG 2.2 AA）

### 交付清单

- **语义化优先**：`header/nav/main/section/article/footer`、`h1→h3` 层级、列表用 `ul/li`、
  键值对用 `dl/dt/dd`；卡片是 `<a href="#/pack/...">`（链接就是导航，可右键新开），
  筛选用原生 `<button>` + `aria-pressed`；没有用 ARIA 去模拟原生控件。
- **名称与角色**：每个控件都有可访问名称；装饰性 SVG 一律 `aria-hidden="true"`；
  异步结果用 `aria-live="polite"` 播报「自带中文：7 个（本站已可下载 0 · 自带中文 7 · 待翻译 15）」。
- **键盘**：跳转链接「跳到主要内容」；三态筛选、卡片、截图条全部可 Tab 到；
  截图条支持方向键，且是「移动焦点 + 切换选中」的可预期行为；无焦点陷阱。
- **焦点可见**：统一 `:focus-visible` 3px 高对比焦点环 + 3px 偏移，深底上始终看得见
  （当前选中色 `hsl(190 96% 72%)` 与底色对比 12:1 以上）。
- **触控目标**：所有按钮/筛选芯片最小高度 44–48px；缩略图按钮 132×74px（移动 118×66px）。
- **对比度**：正文 `--ink` ≈ 17:1，次要文字 `--ink-2` ≈ 9.6:1，第三级 `--ink-3` ≈ 6.4:1，
  三态色均 ≥9:1，卡片描边等纯装饰元素不承担信息。
- **动效**：`prefers-reduced-motion: reduce` 下统一把动画/过渡压到 0.001ms、
  关闭骨架扫光、取消悬停位移、滚动改 `auto`。
- **媒体**：截图都有 `alt`，装饰图 `alt=""`。

### 审计表（自查）

| 问题 | 条款 | 严重度 | 修法 |
|---|---|---|---|
| 状态只用颜色区分 | 1.4.1 颜色使用 | 高 | 色相 + 图标形状 + 文字标签三重编码 |
| 骨架屏只闪不停、读屏无提示 | 4.1.3 状态消息 | 中 | `aria-busy` + `role="status"` 播报筛选结果 |
| 视图切换后焦点留在页面顶部 | 2.4.3 聚焦顺序 | 中 | 切换后给新视图 `h1` 加 `tabindex="-1"` 并聚焦 |
| 横向滚动条溢出被截断（筛选/缩略图） | 1.4.10 重排 | 中 | `overflow-x:auto` + `scroll-snap`，容器内滚动不影响页面 |
| 小图标加载失败导致整张封面变占位图 | 1.1.1 非文本内容 | 低 | 只有 `.card__icon` 失败时仅隐藏自身 |
| 触控目标过小 | 2.5.8 目标尺寸(AA) | 中 | 最小 44px；芯片 48px |
| 安装路径在窄屏被截断成半截 | 1.4.4 调整文本大小 / 1.4.10 | 中 | 窄屏改为折行 `overflow-wrap:anywhere` |
| 详情页事实表标签被长值挤成两行 | 1.4.10 重排 | 低 | `dt{white-space:nowrap}` + `dd{min-width:0}` |

### 纯键盘 + 读屏验证路径

1. `Tab` → 出现「跳到主要内容」→ `Enter` 跳到 `#main`。
2. `Tab` 到筛选条，`←/→` 不行（芯片是按钮，不是单选组），用 `Tab` 逐个走、`Enter` 触发；
   按下后 `aria-live` 会播报新的结果数量。
3. `Tab` 到任意卡片 → `Enter` 进入详情；焦点落在 `<h1>`，读屏会先读包名。
4. `Tab` 到缩略图条 → `←/→` 切换截图，主图 `alt` 随之变化，读屏会播报「第 N 张，共 M 张」。
5. `Shift+Tab` 回到「回到整合包列表」→ `Enter` 返回列表，焦点仍在列表标题上。

## 七、移动端（≤480px，实测过，不是事后补）

简报里点名了参考项目「手机端 8 个显示问题返工一次」。我在这一版里做了**实测**而不是目测：

- 宽度 ≤480px：单列网格、区块间距收窄、Hero 左对齐、`h1` 用 `clamp(30px,9vw,40px)`；
  Hero 按钮拉满等宽；详情页头图改 4:3、图标与标题竖排；安装步骤编号块缩到 44px；
  缩略图 118px 宽；页脚竖排。
- 筛选条：`overflow-x:auto` + `scroll-snap`，任何宽度都不溢出，最后一项也不会贴边裁切。
- 实测记录（这一步发现并修掉了真问题）：
  1. Chrome 无头模式有最小窗口宽度，`--window-size=420` 实际视口是 504px，
     所以「看起来截断」的截图其实是假象——我改用 `html{zoom:1.45}` 把有效视口压到 ≈348 CSS px 复测。
  2. 在 348 CSS px 下 `documentElement.scrollWidth === clientWidth`（504 === 504），
     列表页 / 详情页 / 安装页三个视图都**没有页面级横向溢出**；
     唯二超出视口宽度的是筛选芯片与缩略图条，它们位于横向滚动容器内部，属预期行为。
  3. 修掉两处只在窄屏出现的问题：`facts` 标签被长值挤成「分/类」两行；安装路径被截成半截（改为折行）。

## 八、硬约束的落点

- **许可**：安装说明页与关于页都写清「基于 CFPA 团队与相关模组作者的译名 + CC BY-NC-SA 4.0」；
  **全站无广告位、无付费、无赞助墙**（关于页有明确声明，页脚也有）。
- **安装说明必须显眼**：顶栏常驻入口、Hero 次按钮直达、详情页侧栏有「安装三步」摘要，
  安装页首句就是「汉化没生效，九成是文件放错了位置」，并强调「产物是文件与目录，不是资源包」，
  配「不要这样放 / 正确做法」对照与路径一键复制。
- **三种状态都不能静默隐藏**：图例讲清三态、筛选计数如实显示（含 0）、
  自带中文的包在列表与详情页都明确写「不用来我们这儿找」。
- **两个断点**：桌面 ≥1200px（网格固定三列、容器 1440px）与移动 ≤480px，同文件媒体查询实现。

## 九、已知取舍

- 列表由脚本渲染而非预渲染 HTML：这样数据与站点接口同构、只有一个真源。
  代价是无 JS 时只有 `noscript` 提示（已补），本项目的主要用户是浏览器正常开启 JS 的玩家。
- 下载按钮与「提交翻译请求」在设计稿里只触发反馈条说明「这是设计稿」，
  没有伪造下载地址或虚假的成功状态。
- 页面未做深浅色主题切换：暗底是这套封面驱动方案的成立前提，浅色版需要另做一轮配色验证。
