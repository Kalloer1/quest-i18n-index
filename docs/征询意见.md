> 你是被请来当**独立的批判者**，不是来附和的。这个项目的负责人想听「哪里不对、漏了什么、

## 一、这个项目是什么

**Minecraft Java 版整合包「任务书」汉化站。**

玩家路径：玩到某整合包 → 任务书是英文看不懂 → 来站里找到**这个整合包** →
下载对应版本的任务书汉化 → 按安装说明放进游戏 → 任务界面变中文。

**注意不是模组汉化**——模组本身早由 CFPA 团队汉化完了。这里只做**任务书**（FTB Quests 的任务文本）。

## 二、已经查实的技术事实（都有实测证据，不是推测）

### 2.1 FTB Quests 的文本存放有三代布局

| 布局 | 路径 | 实测来源 | 产出方式 |
|---|---|---|---|
| 分离·目录 | `lang/<locale>/*.snbt` | All the Mods 10 | 新增目录，不碰玩家文件 |
| 分离·单文件 | `lang/<locale>.snbt` | FTB Skies 2 / StoneBlock 4 / OceanBlock 2（均 1.21.1） | 新增文件 |
| **内嵌** | 文本混在 `chapters/*.snbt` 里 | better-mc-forge-bmc4、prominence-2 | **必须改写玩家文件** |

**同一个 MC 版本可并存不同布局**（取决于整合包锁的 FTB Quests 版本）。

### 2.2 探测成本：只读 zip 中央目录

用 HTTP Range 只取 zip 尾部 → 解析 EOCD → 拿到完整文件清单。
实测：190MB 的包只下 **607KB、4.7 秒**；还能按需只取单个文件（约 2 秒）。

陷阱：`Range: bytes=-65536`（后缀）返回 **501**，必须用 `bytes=start-end`；
`edge.forgecdn.net` 上发 Range 返回 **404**，必须先跟随重定向到 `mediafilez.forgecdn.net`。

### 2.3 扫描结果（CF 热度前 100 + Modrinth 前 100）

| 布局 | CurseForge | Modrinth |
|---|---:|---:|
| 分离·目录 | 8 | 0 |
| 分离·单文件 | 14 | 2 |
| 内嵌 | 28 | 7 |
| 无任务书 | 33 | 89 |

可产出 22 个（CF），其中 **7 个已自带中文** → **15 个有缺口**。
Modrinth 侧几乎没有任务书重的包（**目标市场在 CurseForge**）。

### 2.4 反直觉的事实：越热门越不缺汉化

ATM 系列、FTB 系列**自己就带社区中文**并随包分发。
⇒ 缺口集中在**中等偏冷**的包上。

### 2.5 术语库问题已被别人解决

`VM-Chinese-translate-group/i18n-Dict-Extender` 的 `Dict-Mini.json`：
**395,746 条、19.8MB、每周五更新（实测最新 2026-10-16）**，
且已合并**模组官方仓库的译文**（正是 CFPA 缺的那块）。

实测查得：`Create` → `["制造","创建","新建","制作","机械动力",...]`、
`Holystone` → `["圣石"]`、`Farmers Delight` → `["农夫乐事"]`。

**但 36,110 / 395,746 条有多个候选**（`Create` 有 8 个），直接取第一个会翻错。

### 2.6 已有整合包级汉化的先例（复数）

- `VM-Chinese-translate-group`：2022-11-19 成立，73 个仓库，自述「专注于汉化MC整合包与地图」，
  **昨天（2026-10-16）还在推代码**。对照我们的 15 个缺口包，他们覆盖了 **Craftoria** 与 **Techopolis-3**。
- `CFPAOrg/Modpack-GuideBook-i18n`：35 包 / 127 版本，**2023-10 停更**。
- 已有工具：`FTBQuestLangSpliter`（按章节拆/合 SNBT）、
  `translate-tools`（**FTBQ 颜色字符合法检查** + snbt⇄json 互转）。

## 三、已经定案的决策（见 `docs/adr/`）

| ADR | 决定 |
|---|---|
| 0001 | 用「只读 zip 中央目录」探测，不下载整包，不用依赖列表法（依赖列表法实测被否决：FTB Quests 本体不在 Modrinth 上） |
| 0002 | 探测覆盖三种布局；**生产路径只做「译文分离」两种**，内嵌只识别不产出 |
| 0003 | 定位「补缺口」：只为没有中文的整合包产出；自带中文的只标注不重译 |
| 0004 | 接受 **CC BY-NC-SA 4.0**，站点非商业，署名 CFPA 与模组作者 |
| 0005 | 建全局「模组术语库」，来源合并 CFPA 包与模组 jar |
| — | 术语记忆用**英文原文**（剥色码）为键，跨整合包复用 |
| — | 校验：键集合/内嵌指令/数组元素数/缩进=**阻断**；色码数量/译文与英文相同=**警告** |
| — | 分块：按**顶层条目**（约 40 条/块），条目永不切开 |

## 四、现在正在纠结的三个问题

**Q1：术语库改用现成的 `Dict-Mini.json`（19.8MB、39.5 万条、每周更新、含官方译文），
还是按原计划自己扫模组 jar（约 6 秒/模组、估计 3~7 小时一次性）？**
当前倾向：用现成的。理由：已包含扫 jar 能拿到的核心内容，且**有维护者**，
比自己扫更能跟上；实测它缺 `Alex's Mobs` 这类条目，但可以先跑起来再补。

**Q2：多候选怎么消歧？**（`Create` 有 8 个候选，含「创建」和「机械动力」）
当前倾向：**用整合包的模组列表消歧**——读整合包清单拿到它装了哪些模组，
`Create` 命中模组 `create` → 必取「机械动力」；不在模组表里的词才让模型选。

**Q3：站上要不要同时列出 VM / CFPA 已有的汉化（哪怕不是我们做的）？**
当前倾向：列，并链接过去。让本站成为「**汉化索引**」——
玩家从这里就能知道「这个包有没有汉化、在哪」。理由：玩家的真实痛点是
「我玩的整合包有没有中文、去哪找」，而现状是他得分别去 VM 官网、CFPA、GitHub 翻。
且这也让站点在**一个字都还没翻**的时候就有用。
