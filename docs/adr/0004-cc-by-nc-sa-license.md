# 0004. 接受 CC BY-NC-SA 4.0 约束，站点保持非商业

日期：2026-10-17
状态：已接受

## 背景

术语来源有两个，许可情况都查过：

| 来源 | 许可 | 实测证据 |
|---|---|---|
| CFPA 成品资源包 | **CC BY-NC-SA 4.0**（署名—非商业—相同方式共享） | 包内 `LICENSE` 文件首行 + 仓库 badge |
| 模组自身 `zh_cn.json` | **不透明** | `Creators-of-Create/Create` 在 GitHub 上是 `NOASSERTION` / "Other"，根目录 `LICENSE` 返回 **404** |

CFPA 包内含署名要求，`README.txt` 原文：

> 署名：CFPA团队（完整贡献者名单：https://github.com/CFPAOrg/Minecraft-Mod-Language-Package/graphs/contributors）

## 决策

**接受 CC BY-NC-SA 4.0：站点保持非商业；本站产出的任务书汉化与术语库标注 CC BY-NC-SA 4.0，
并署名 CFPA 团队与相关模组作者。**

## 理由

- **避开 CFPA 并不能换来清白**：模组自身的许可比 CFPA 更不透明（`NOASSERTION`、
  无 LICENSE 文件）。只改用模组 jar 的术语，等于把一种不透明换成另一种，
  还白丢 CFPA 那份 12 万多条的数据（实测 1.20 包共 **126,813 条**、597 个语言文件）。
- **不使用任何外部术语并不现实**：纯靠模型翻译质量最差，而且输出**仍可能**与 CFPA 译文雷同，
  反而更说不清；主动接受许可并署名，比事后解释要诚实得多。
- **本站本来就没有商业化打算**，非商业条款不构成实际限制。

## 后果

- 站点**不得接入广告、付费、赞助墙**等任何商业形态。若将来要商业化，**必须重做术语来源**。
- 产出文件头与下载页必须带署名与许可声明，至少包含：
  - `CC BY-NC-SA 4.0` 许可标识
  - CFPA 团队署名（含贡献者名单链接）
  - 使用到的模组作者署名
- 术语库文件（JSON）本身也要带许可与来源元数据，避免被当成"无主数据"二次分发。
- 我们**不重分发**模组语言文件本身，只产出任务书译文；术语库作为参考数据使用。
