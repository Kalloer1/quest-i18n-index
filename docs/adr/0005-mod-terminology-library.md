# 0005. 建「模组术语库」：合并 CFPA 成品包与模组自身 jar

日期：2026-10-17
状态：已接受

## 背景

任务书文本里会直接出现模组物品/方块名与模组名。模型不知道这些专有名词的官方中文译法，
会按字面意思翻错——典型例子是 **`Create` 被翻成「创造」而不是「机械动力」**。

实测两个可用来源：

| 来源 | 覆盖 | 获取成本 | 实测数据 |
|---|---|---|---|
| **CFPA 成品资源包** | 597 个语言文件、**126,813 条** | **一次下载 2.1 MB**（1.20 版） | `Minecraft-Mod-Language-Modpack-1-20.zip` |
| **模组自身 jar** | 每个模组的完整 zh_cn | ~6 秒/模组，只下 ~6 KB | create 3619 条、botania 3485 条、farmers-delight 479 条 |

**两者不可互相替代**（实测）：

- CFPA 的包是**覆盖层**，不是完整术语表——create 在里面只有 **120 条**，
  而 Create 自身 jar 有 **3619 条**。
- **模组名只在 jar 里**——CFPA 包里 create 的 `itemGroup.*` 键数量为 **0**。

模组自身 jar 里 `itemGroup.*` 的 en↔zh 配对（实测，全部正确）：

```
Create                   → 机械动力
Create's Building Blocks → 机械动力丨建筑方块
Botania                  → 植物魔法
Farmer's Delight         → 农夫乐事
```

## 决策

**建立一个全局「模组术语库」，来源为两者合并；范围限定为「本站要服务的整合包所涉及的模组」。**

具体做法：

1. CFPA 成品包按 MC 版本各下载一份（每个约 2~6 MB），抽取全部条目。
2. 对候选整合包的模组 jar，逐个读中央目录 → 取出 `assets/<ns>/lang/zh_cn.json`。
   **英文侧不需要读**：`itemGroup.<modid>` 的英文值就是模组显示名，
   而该名字从 Modrinth / CurseForge 的 `title` 字段免费可得。
3. 合并去重后缓存成全局 JSON，模组名单独成表。

## 理由

- **成本是一次性的**：模组译名与术语不随整合包变化，建一次全局缓存即可长期复用。
- **范围天然有界**：任务书里提到的物品名必然来自该整合包自己装的那批模组，
  所以"要服务的整合包"就是自然的边界，不需要全量扫上万模组。
- **额外收益**：模组 jar 的 zh_cn 就是该模组的权威术语表，
  用它能让任务书里的物品名与**玩家在游戏里实际看到的**保持一致——这是质量上最大的杠杆。

## 后果

- **必须区分两个不同的东西，命名不得混用**（混用会出破坏性错误，光影项目已踩过）：
  - **模组术语库**：从模组 jar 与 CFPA 包抽取的**只读**权威译名，来源是别人。
  - **站点术语记忆**：本站翻译产出的 en↔zh 对照，来源是我们自己，随翻译增长。
    光影项目对应物是 `site/data/glossary.json`（39,448 条），**不可与术语库混为一谈**。
- 术语库需带许可与来源元数据（见 ADR-0004）。
- 模组名键**并非 100% 覆盖**（实测 jei、curios 的 zh_cn 里没有 `itemGroup.*`），
  缺失时需有降级策略，不能假装一定拿得到。
