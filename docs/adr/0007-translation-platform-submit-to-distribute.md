# 0007. 站点定位：玩家提交 → 自动翻译 → 双通道分发（取代 0003 与 0006）

日期：2026-10-18
状态：**已接受（2026-10-18 用户确认）**
取代：`0003-fill-the-gap-positioning.md`、`0006-site-is-the-goal-verify-then-index-mvp.md`

## 背景

前两份 ADR 把本项目定成了一个**只放链接、一个字都不翻**的索引站：

| 文档 | 原文 |
|---|---|
| `ADR-0006` | 「**明确不做**：翻译、术语库、消歧、校验器、SNBT 解析、产出流水线。**全部不做。**」 |
| `ADR-0006` | 「先做『整合包任务书汉化索引』，**一个字都不翻**；在索引证明有真实需求之后，再决定是否上翻译流水线。」 |
| `ADR-0003` | 「站点定位为『补缺口』：只为没有中文的整合包产出汉化。」（但产出被 0006 推迟到「以后」） |
| `.scratch/index-mvp/spec.md` | 「明确不做：翻译……**「求」按钮**、账号系统、广告。」 |

**这个定位与用户的实际意图不符。** 用户 2026-10-18 明确：

> 我这个网站本来就是让玩家提交整合包链接，然后我们就可以启动一套自动化翻译流程对它进行翻译。
> 如果这个整合包没有 FTB Quests 任务模组的话，就直接跳过不翻译。
> 然后我们还会提供下载链接，比如对应的 GitHub 仓库链接，还会上传到夸克网盘，提供夸克网盘链接作为国内镜像。

即：**「求」不是索引的附属验证手段，而是站点的输入端；翻译流水线不是「以后再说」，而是站点的核心。**

同一套模式用户已经在**光影汉化站**（`E:/project/shader-i18n-site`，线上 `shader.mccnp.top`）跑通过，
且已产出 601 个 `zh_CN.lang`、542 个光影有汉化、39,448 条术语记忆、155 项测试全绿。
本 ADR 的决策是**照搬那套骨架**，不另造一套。

## 决策

1. **站点定位**：整合包任务书汉化**翻译平台**。链路为
   **玩家提交 → 自动翻译 → 质量闸门 → 双通道分发（GitHub 仓库 + 夸克网盘镜像）**。
2. **只做 FTB Quests 任务书**。整合包不含 FTB Quests 时**直接跳过**，不翻译、不产出。
   （用户 2026-10-18 明确。非 FTB 任务书系统——如 SkyFactory 5 用的 Checklist——不在范围内。）
3. **产出形态**：**覆盖式补丁包 zip**。玩家下载后解压覆盖到整合包根目录。
   这与社区主流一致（见 §为什么用覆盖式）。
4. **架构照搬光影站**，逐环节对应，不重新设计：
   | 环节 | 光影站实现 | 本项目 |
   |---|---|---|
   | 采集 | Actions 每日同步 Modrinth + CurseForge 目录 | 已有：`scan-cf500.tsv` 500 条 + `pack-metadata.json` 500 条全字段 |
   | 提交 | `/request` 表单 → Worker（口令 + CORS + 链接校验）→ **KV 队列**（权威状态源） | 同一套 |
   | 触发 | Worker 调 GitHub API `workflow_dispatch` | 同一套 |
   | 翻译 | `pipeline.mjs`：筛候选 → 术语记忆精确命中 → LLM 分块翻译 | 目标换成 FTB Quests 的 SNBT |
   | 闸门 | `validate-lang.mjs`：键集合 + `§` 格式码 + 占位符 + BOM | 色码 `&` + 占位符 + 键集合 + SNBT 结构 |
   | 镜像 | `mirror.mjs` 上传夸克网盘，失败不阻断、留空则不渲染按钮 | 同一套，产物是补丁包 zip |
   | 发布 | 显式路径 `git add` → push → `deploy.yml`（测试 → 校验 → 构建 → Worker → Pages） | 同一套 |
   | 下载 | 详情页给文件下载 + 夸克镜像按钮 | 详情页给 zip 下载 + GitHub 仓库 + 夸克镜像 |
5. **`ADR-0002` 的「内嵌不可做」改为「内嵌走覆盖式产出」**。
   该 ADR 附录证明的是「**没有语言注入机制**」，因此内嵌包**只能改写文件**——
   它证明的是路径唯一，不是路径不存在。产出方式见 §为什么用覆盖式。

## 为什么用覆盖式

`ADR-0002` 附录的实测结论（50 个包，布局与 MC 版本**零交叉**）成立且仍有效：

> MC ≤ 1.20.1 的整合包所带的 FTB Quests 里，翻译系统根本不存在——没有 `TranslationManager`、
> 没有 `lang/` 读取路径、没有任何可注入译文的机制。

**但它推出的是「只能改写文件」，不是「不能做」。** 社区早就在这么做：

| 先例 | 做法 | 覆盖范围 |
|---|---|---|
| CFPA `Modpack-GuideBook-i18n` | 每「整合包 × 版本」两个 zip（windows / linux），解压覆盖到 MC 根目录 | 35 包 / 127 版本；含 `config/ftbquests/normal/chapters/<chapterId>/<questId>.nbt` |
| VM 汉化组 | 覆盖式补丁包 + 安装组件，官网统一文案「解压并覆盖相应文件」 | 含 9 个内嵌布局包（Create: Astral、FTB StoneBlock 3、MC Eternal 2…） |
| Kiwi233 `Translation-of-GTNH` | 重打包 + 每日构建 `nightly-*.7z` | 492 star |

CFPA 的 README 开篇即写「**请注意，一定要在替换之前备份游戏**」，并明写该模式的已知失败模式：

> 这些翻译极具时效性，**如果整合包更新，那么意味着这些文件可能无法使用**。

⇒ **这是社区已知并接受的失败模式**，不是本项目新引入的风险。`ADR-0002` 的立场比整个社区都保守。

## 与旧 ADR 的冲突处理

- `ADR-0003`（只补缺口、不重译）**部分保留**：
  「不重译社区已有成果」这条仍然成立，但**判断依据从「不产出」改为「不覆盖」**——
  即 VM / CFPA 已覆盖的包，本站不重复产出，只链接（实测 VM 覆盖 28 条，其中 9 条是内嵌包）。
- `ADR-0006`（索引 MVP、不做翻译）**整体作废**。它的「先验证需求再上流水线」排序被用户明确推翻：
  提交入口本身就是需求入口，不需要先做一个纯索引来验证。
- `ADR-0004`（CC BY-NC-SA / 非商业）**必须重写**：本站从「只分发 URL」变成「分发衍生作品」，
  须署名 CFPA 团队与相关模组作者、产出文件带许可标识、非商业条款约束到译文本身。
- `ADR-0005`（模组术语库 vs 站点术语记忆）**继续有效**，且从「将来用」变成「现在就要用」——
  它是流水线的术语来源，对应光影站的 `glossary.json`（39,448 条）。

## 后果

- 站点从静态单页变成**有后端的应用**：Cloudflare Worker + KV + GitHub Actions + Pages。
- 需要新增：提交表单、队列与状态机（`待翻译 → 翻译中 → 已完成 / 镜像缺失 / 失败`）、
  SNBT 解析与序列化、术语记忆、质量闸门、补丁包打包、夸克网盘镜像、发布流水线。
- **内嵌包（104 条）从「不可做」变成「可做」**，但产出必须改写玩家文件，因此：
  补丁包必须自带备份提示，且**上游更新后可能失效**（与社区一致）。
- 「查」这条链路仍然保留且**必须先修准**：数据不准会让玩家提交假需求。
  （2026-10-18 已修：图标 57→500、标题 57→500、VM 覆盖 11→28。）

## 已决（2026-10-18 用户确认：全部沿用光影站做法）

1. **关站判据**：`ADR-0006` 的「两个月无流量即关站」**作废**。
   新判据基于**提交量与产出量**，不是访问量——连续 6 个月无新增提交且无新增产出，才考虑关站。
2. **术语记忆来源**：**自建** `glossary.json`（与光影站同构），从 CFPA 的模组术语库起步做种子，
   之后随每次翻译回写增长。不依赖外部服务的实时查询。
3. **LLM 网关**：**沿用光影站那一套**——免费层优先（公开 API），失败落自建网关模型池。
4. **内嵌包产出方式**：**整体覆盖式**（社区主流）。但落地前**必须先验证 SNBT 无损往返**
   （对应工单 `02`/`03`）。若往返无损，则按 quest ID 合并作为可选增强；若无法保证无损，只做整体覆盖。
5. **审核环节**：**沿用「无人审核」**。唯一质量闸门是校验器（`validate-quests.mjs`），
   校验不过即中止该条产出，不写文件、不登记。
